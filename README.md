# Moa · 모아

취향을 모아, 맞는 사람을 알아보는 **취향 기반 소개팅 웹앱** (개인 프로젝트 데모)

내 프로필과 찾는 상대 조건을 입력하면, 가상 프로필 40명(모두 20대)을 **필수 조건으로 거른 뒤 정해진 점수표로 계산**해 순위를 매기고, 왜 그 사람이 1위인지 항목별 점수로 보여 줍니다.

> 궁합 점수는 서로 설정한 취향을 비교한 결과일 뿐, 실제 관계의 성공을 보장하지 않아요.

## GitHub에 올려서 웹사이트로 열기

이 프로젝트에는 자동 배포 설정(`.github/workflows/main.yml`)이 들어 있어요. 저장소에 올리면 GitHub가 알아서 테스트 → 빌드 → 배포를 해요.

1. GitHub에서 새 저장소를 만들어요. (예: `moa`, Public)
2. 압축을 푼 `moa` 폴더에서 아래 명령을 실행해요. (`아이디`는 내 GitHub 아이디로)
   ```bash
   git init
   git add .
   git commit -m "Moa 첫 버전"
   git branch -M main
   git remote add origin https://github.com/아이디/moa.git
   git push -u origin main
   ```
3. 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿔요.
4. **Actions** 탭에서 "Deploy to GitHub Pages"가 초록색 체크가 될 때까지 1~2분 기다려요. (Source를 바꾸기 전에 실행돼 실패했다면, 그 실행을 열고 **Re-run all jobs**를 눌러요.)
5. `https://아이디.github.io/moa/` 로 접속하면 돼요.

> 웹 브라우저로 파일을 드래그해서 올릴 때는 `.github` 폴더가 숨김 폴더라 빠지기 쉬워요. 그럴 땐 저장소에서 **Add file → Create new file**로 경로를 `.github/workflows/main.yml`로 입력하고 내용을 붙여 넣으세요. `node_modules`, `dist` 폴더는 올리지 않아도 돼요.

이후에는 코드를 고치고 `git push`만 하면 사이트가 자동으로 업데이트돼요. 테스트나 빌드가 실패하면 배포되지 않고 Actions 탭에 빨간 X가 표시돼요.

## 실행 방법

Node.js 20 이상이 필요해요.

```bash
npm install        # 의존성 설치
npm run dev        # 개발 서버 → 터미널에 나오는 주소(보통 http://localhost:5173)로 접속
npm test           # 매칭 알고리즘 테스트 (Vitest)
npm run build      # 타입 검사 + 배포용 빌드 (dist/ 폴더)
npm run preview    # 빌드 결과 미리보기
```

GitHub Pages 배포: `npm run build` 후 `dist/` 폴더를 올리면 돼요. `base: './'`와 해시 라우팅(`#/feed`)을 쓰기 때문에 저장소 하위 경로에서도 그대로 동작해요.

## 매칭 규칙

### 1단계: 필수 조건 필터 (`filters.ts`)

사용자가 **직접 켜거나 고른 조건만** 필터로 씁니다. 비어 있는 조건은 필터가 아니에요.

| 조건 | 언제 적용되나 | 상대 정보가 없으면 |
|---|---|---|
| 상대 성별 | 성별을 고르면 | 제외 (이유: 정보 없음) |
| 나이 | 범위 입력 **+ 필수 토글** | — |
| 키 | 범위 입력 **+ 필수 토글** (점수표에 없어 필터 전용) | — |
| 종교 | 선호 종교 선택 **+ 필수 토글** | 제외 |
| 소득 구간 | 구간을 하나 이상 고르면 (필터 전용) | 제외 (비공개) |
| 여행 취향 | 내 여행 취향이 있고 **필수 토글** | 제외 |

- 나 자신(`id`가 같은 프로필)은 항상 후보에서 빠지고, 제외 목록에도 표시하지 않아요.
- 제외된 후보는 **점수를 계산하지 않고**, 제외 이유를 화면에 보여 줘요.
- 통과한 후보가 0명이면 추천하지 않고, 조건별로 몇 명을 걸렀는지와 "이 조건 풀기" 버튼을 보여 줘요.

### 2단계: 점수 계산 (`score.ts`, 점수표는 `scoreTable.ts`)

| 항목 | 점수 | 계산 |
|---|---|---|
| 선호 나이 범위 | 15 | 범위 안이면 15 |
| 성격 유형 일치 | 18 | 최대 3개 선택, 겹치는 항목 × 6 |
| 공통 취미 | 30 | 최대 5개 선택, 겹치는 항목 × 6 |
| 음악 취향 일치 | 16 | 최대 4개 선택, 겹치는 항목 × 4 |
| 여행 취향 일치 | 10 | 즉흥형/계획형이 같으면 10 |
| 종교 선호 일치 | 6 | 선호 종교와 같으면 6 |
| 스타일 선호 태그 | 5 | 바라는 태그가 하나라도 겹치면 5 |
| **합계** | **100** | |

- 내가 설정하지 않은 항목은 **0점이고 "미사용"으로 표시**해요. (예: 선호 나이를 비우면 나이 15점은 누구에게도 주지 않음)
- 항목당 점수는 최대점을 넘지 않아요.
- 성격·취미·음악은 선택 한도(최대점 ÷ 항목당 점수)만큼만 고를 수 있고, 캐릭터들도 모두 이 한도만큼 취향을 가져요. 그래서 취향이 완벽히 맞으면 실제로 100점이 나와요.

### 3단계: 정렬 (`recommend.ts`)

총점 높은 순 → 동점이면 공통 취미가 많은 순 → 그래도 같으면 닉네임 가나다순.

### 점수표 바꾸기

`src/matching/scoreTable.ts`의 `DEFAULT_SCORE_TABLE`에서 `points`, `perItem`, `max`만 고치면 계산·화면·설명·선택 한도가 모두 따라 바뀌어요. 선택 한도를 바꾸면 캐릭터 데이터의 취향 개수도 맞춰 주세요 (테스트가 검사해요).

## 테스트 항목 (`npm test`)

- 점수표 총점 100점, 항목별 배점이 요구사항과 일치
- 특정 가상 프로필과의 점수를 항목별로 손으로 계산한 값과 비교 (해질녘 = 53점)
- 모든 항목이 맞으면 정확히 100점, 아무것도 설정하지 않으면 0점
- 설정하지 않은 항목은 점수에 반영하지 않음
- 필수 토글을 켜지 않은 조건은 필터로 쓰지 않음 / 켠 조건은 이유와 함께 제외
- 추천 순위·점수 합계·동점 처리 규칙
- 나 자신 제외 (나와 똑같은 프로필이 섞여 있어도)
- 후보 0명, 빈 후보 풀
- 가상 프로필 40명 전체에서 총점 = 항목 합계, 내림차순

## 내 LLM 연결하기 (Moa의 한마디)

추천 1위 카드 아래와 궁합 상세 화면의 **"Moa의 한마디"**에서, 운영자 컴퓨터의 Ollama 모델이 두 사람을 다 아는 친구처럼 상대를 소개해 줘요.

- **역할 분담:** 점수 계산·순위는 Moa 매칭 알고리즘이 하고, LLM은 코드가 골라 준 말할 거리(겹치는 취향 최대 2개 + 다른 점 1개)만 받아 소개 문장을 써요.
- **모델:** 기본 `exaone3.5:2.4b` (없으면 `qwen3:4b-instruct`).
- **검증:** LLM 문장에 계산 결과에 없는 숫자가 나오면 화면에 경고를 띄워요.
- **코드:** `src/services/llm.ts`, `src/components/LlmExplain.tsx`, 테스트 `src/services/llm.test.ts`

### 다른 사람 컴퓨터에서도 쓰기 (Windows)
1. `tools` 폴더의 `Moa_LLM_켜기.bat`과 `moa-llm-share.ps1`을 **같은 폴더**에 두고 `Moa_LLM_켜기.bat`을 더블클릭해요.
2. 스크립트가 Ollama를 켜고, EXAONE 모델을 확인하고, Cloudflare 임시 주소를 만든 뒤 **공유 링크**를 보여 줘요. (클립보드에도 복사돼요)
   - 예: `https://soong9ing.github.io/moa/?llm=https%3A%2F%2Fxxxx.trycloudflare.com`
3. 이 링크로 들어온 사람은 누구나 Moa의 한마디를 받을 수 있어요. 링크의 LLM 주소는 그 사람 브라우저에 저장되고, 주소창에서는 지워져요.
4. **창을 켜 둔 동안에만** 동작해요. 창을 닫았다 다시 켜면 링크가 바뀌니 새 링크를 다시 보내요.

**문지기(moa-llm-share.ps1)가 막는 것:** Ollama를 그대로 인터넷에 열지 않고, 앞에 문지기를 둬요.
- 통과: 모델 목록 보기(`GET /api/tags`, 허용 모델만 보여 줌), 소개 글 쓰기(`POST /api/chat`)
- 차단: 모델 설치·삭제 등 나머지 기능 전부, 허용되지 않은 모델, Moa 사이트가 아닌 곳의 요청, 16KB 넘는 요청
- 글 길이·온도 같은 옵션은 문지기가 고정하고, 1분에 30번까지만 받아요. 요청 내용은 화면·파일에 남기지 않아요.
- 사이트 쪽에서도 `?llm=`에는 `https://*.trycloudflare.com`과 내 컴퓨터 주소만 받아요. (수상한 링크로 정보가 엉뚱한 서버에 가지 않게)

> 처음 실행할 때 Cloudflare 공식 프로그램 `cloudflared`(약 60MB)를 GitHub에서 한 번 내려받아 `%LOCALAPPDATA%\Moa`에 둬요.
> 매번 같은 주소를 쓰고 싶으면 Cloudflare 계정의 이름 있는 터널이나 ngrok 고정 도메인을 쓰면 돼요.

## Supabase 연결 (진짜 로그인 · 가입자 수)

**지금은 꺼져 있어요.** Moa는 서버 없는 가상 앱(데모 모드)으로 운영해요. 아래는 나중에 다시 켤 때를 위한 설명이에요. 켜려면 `src/services/supabaseConfig.ts`의 `FORCE_DEMO` 기본값을 바꾸거나 `VITE_MOA_DEMO=false`로 빌드하세요.

켰을 때 동작:

- **회원가입·로그인:** 이메일 + 비밀번호 (Supabase Auth)
- **내 프로필·찾는 상대 조건:** Supabase `profiles` 테이블에 저장 → 다른 기기에서도 이어져요. 내 프로필은 나만 볼 수 있어요 (RLS).
- **현재 가입자 수:** 모든 방문자가 같은 숫자를 봐요 (`member_count()` 함수, 숫자만 공개).
- **회원 탈퇴:** 내 프로필 화면 → 회원 탈퇴 (`delete_my_account()` 함수)
- **아직 이 브라우저에만 저장:** 좋아요·대화·차단 기록
- **추천 상대:** 여전히 Moa 캐릭터 40명 (실제 가입자끼리의 추천·대화는 다음 단계)

### 처음 한 번 해야 할 설정
1. Supabase 대시보드 → **SQL Editor** → `supabase/schema.sql` 전체를 붙여 넣고 **Run**
2. **Authentication → Sign In / Providers → Email** 에서 **Confirm email** 끄기
   (Supabase 기본 메일은 팀원 주소로만, 시간당 2통만 보낼 수 있어서 일반 사용자는 인증 메일을 받지 못해요)
3. **Authentication → URL Configuration** 의 **Site URL** 을 `https://soong9ing.github.io/moa/` 로 설정

### 키에 대해
- `sb_publishable_…` 키는 공개용이라 코드에 들어가 있어도 괜찮아요. 데이터는 RLS 규칙이 지켜요.
- `sb_secret_…` / `service_role` 키는 절대 코드나 GitHub에 올리지 마세요.
- 기본은 데모 모드예요. `VITE_MOA_DEMO=false` 로 빌드하면 Supabase에 연결돼요.

## 데모 모드와 외부 서비스 설정이 필요한 기능

현재 버전에는 인증 서버·데이터베이스가 **연결되어 있지 않아요.** 상대 프로필은 모두 Moa가 만든 캐릭터이고, 이 사실은 첫 화면 하단·로그인 화면·채팅방 상단·프로필 상세의 "Moa 캐릭터" 표시로 안내해요.

| 기능 | 지금 동작 방식 | 실제 서비스로 만들려면 |
|---|---|---|
| 회원가입·로그인 | 이메일+닉네임으로 이 브라우저 안에서만 계정 구분. **비밀번호를 받지 않음** (보안 기능 아님) | Supabase Auth, Firebase Auth 등 |
| 프로필·조건·좋아요 저장 | 브라우저 localStorage | 데이터베이스 (예: Supabase Postgres) |
| 매칭 후보 | 가상 프로필 40명만 | DB의 실제 사용자 프로필을 후보 풀에 추가 (`kind: 'user'`) |
| 채팅 | 캐릭터가 미리 준비된 문장으로 자동 답장 (채팅방 상단에 안내). 채팅방 나가기·차단 지원 | 실시간 메시지 서비스 (Supabase Realtime, Firebase 등) |

### 실제 로그인·채팅 연결하기

1. `src/services/auth.ts`의 `AuthService` 인터페이스를 실제 서비스로 구현해요. (비밀번호·소셜 로그인은 반드시 인증 서비스에 맡기세요)
2. `AppStore.tsx`가 `demoAuth` 대신 그 구현을 쓰도록 바꾸고, 계정 데이터 저장을 DB 호출로 바꿔요.
3. `pool`(현재 `MOCK_PROFILES`)에 DB의 실제 사용자를 합쳐요. 매칭 알고리즘은 그대로 쓸 수 있어요.
4. `src/services/backend.ts`의 `mode`를 `'live'`로 바꾸고, 가상 프로필 채팅만 데모로 남겨 두세요.
5. API 키는 `.env`에 `VITE_` 접두사로 넣고, `.env`는 Git에 올리지 마세요(`.gitignore`에 포함됨). 실제 사용자 데이터를 다루면 DB 접근 규칙(RLS 등)도 꼭 설정하세요.
